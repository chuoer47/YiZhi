### 1. 项目背景与目标

本系统针对法律从业者（律师、法官、企业法务、法律AI开发者）在**类案检索**场景下的痛点，开发一款智能法律AI产品——**裁判规则库**。

**传统痛点**（来自PDF文件）：
- 需反复调整关键词，检索结果数量极少或过多；
- 人工筛选相似性、裁判理由、裁判规则，耗时长且易遗漏；
- 输出缺乏结构化，裁判观点分散，无系统性分析。

**AI创新目标**：
- 支持**自然语言检索**（输入大白话案情即可找到高度相似案例）；
- 自动生成**精简结构化Excel类案检索表** + **Word类案检索报告**；
- 重点解决“裁判规则提取”与“关键裁判结论分类”，实现从海量裁判文书中快速提炼可复用的裁判逻辑。

**产品定位**：智慧法律应用中的**工具型AI**（方向2），可扩展为智能体或系统解决方案（方向1/3）。

**新增技术基础**：已完成基础架构并提供 `deli_api` 轻量级集成包（封装得理开放平台API），支持 `queryListCase`（案例检索）和 `queryListLaw`（法律法规检索），并提供 LangChain 检索器与工具，完美对接本系统。

### 2. 核心功能需求

#### 2.1 输入需求
- 支持**自然语言输入**：用户输入案件基本案情（无需设计关键词）。
- 可选过滤条件：地域、法院层级、时间范围、案由、行业等。
- 支持上传参考案例或图片/描述作为检索补充。
- 通过 `deli_api` 的 `CaseRetriever` / `create_search_cases_tool` 直接调用后端 API，实现语义检索（`field_name="semantic"`）。

#### 2.2 输出需求（核心）
系统必须输出**两类核心产物**：

**A. Excel类案检索表（精简版 + 个性化版）**

1. **表头基础框架（固定通用模板）**  

   | 字段（中文）       | 是否必选 | 说明                  |
   |--------------------|----------|-----------------------|
   | 序号               | 是      | 自动编号              |
   | 案例名称           | 是      | 完整标题              |
   | 案号               | 是      | 完整案号              |
   | 审理法院           | 是      | 全称                  |
   | 省份               | 是      | 自动提取              |
   | 案由               | 是      | 完整案由              |
   | 审判程序           | 是      | 一审/二审/再审等      |
   | 审判日期           | 是      | 裁判日期              |
   | 文书类型           | 是      | 判决书/裁定书等       |
   | 裁判理由           | 是      | **法院认为**原文（保留） |
   | 裁判结果           | 是      | 完整裁判主文          |

2. **必须额外补充的两类核心信息**（重点要求）：
   - **主要原因**（精简版裁判理由）：从“法院认为”中**精简提炼**直接相关的核心裁判逻辑（一句话或几句话）。
   - **关键裁判结论**（重点定制板块）：自动分类识别并结构化输出以下三类：
     - **权利类定性结论**：是否侵权、是否违约、合同是否有效、是否构成妨害相邻关系等；
     - **金额类**：判赔/补偿/罚款的具体金额、计算依据、是否支持部分请求等；
     - **行为类**：判令拆除、赔礼道歉、恢复原状、禁止建造等具体行为义务。

3. **个性化定制字段**（根据案件类型动态生成，不统一套用）  
   示例（相邻关系纠纷-采光日照案例，来自Excel文件）：是否构成侵权、是否判赔/判驳回/判拆、拆除类型、赔偿金额依据、备注等。

**最精简版Excel（建议6大核心列）**：
1. 审理法院  
2. 案号  
3. 法院认为（精简后）  
4. 裁判结果  
5. 主要原因  
6. 关键裁判结论（权利类/金额类/行为类）

**B. Word类案检索报告（结构化文档）**
- 案例检索概述（检索说明、检索目标、数据量统计）
- 核心裁判规则归纳（统计支持/不支持比例，可视化图表）
- 案件争议焦点归纳
- 目标案件裁判思路倾向预测
- 专家观点建议（可从律所/学界公开信息补充）
- 高度相关经典案例原文（最高院/高院优先，相似度Top3-5）
- 数据可视化（饼图、柱状图：判决拆除比例、判赔比例等）

#### 2.3 附加智能能力
- **相关性评估**：自动判断案例复杂程度、与目标案情匹配度（基于 `deli_api` 返回的 `score`）。
- **法律法规时效性提醒**：调用 `queryListLaw` 标注民法典前后适用差异、地方司法政策变化。
- **输出格式适配**：支持用户自定义列顺序、导出Excel/Word/PDF。

### 3. 数据处理与AI能力要求

- **输入**：裁判文书全文（通过 `deli_api` 的 `queryListCase` 批量检索）。
- **处理流程**（新增 deli_api 集成）：
  1. **检索层**：使用 `deli_api.CaseRetriever` 或 `create_search_cases_tool` + `DeliLegalClient` 进行语义检索（支持 `page_size`、`time_liness_type_arr` 等参数）。
  2. **后处理层**：GPT-5.3-codex 对检索结果进行结构化提取（精简“法院认为”、分类“关键裁判结论”）。
  3. **生成层**：自动生成Excel（pandas）+ Word（python-docx 或模板引擎）。
- **准确性要求**：必须符合法律专业性，由法律人士验证。
- **伦理与合规**：输出标注数据来源、时效性，不提供法律意见，仅供参考。
- **异常处理**：使用 `deli_api` 提供的标准化异常体系（`DeliLegalError` 家族），确保系统鲁棒性。

### 4. 技术实现路径（符合比赛要求 & deli_api 集成）

- **大模型**：GPT-5.3-codex（核心推理、文本生成、结构化提取、Prompt 工程）。
- **平台API**：得理开放平台API（`queryListCase` + `queryListLaw`），通过 **deli_api** 轻量级集成包实现标准化调用。
- **deli_api 集成方式**（基于 README.md）：
  - **底层客户端**：`DeliLegalClient.from_env()` 处理认证、HTTP 请求、结果标准化。
  - **检索器**：`CaseRetriever` / `LawRetriever`（LangChain 兼容，返回 `Document` 对象）。
  - **工具**：`create_search_cases_tool` / `create_search_laws_tool`（供智能体调用，返回 JSON）。
  - **返回模型**：`LegalHit` 对象（含 `score`、`citation`、`case_no`、`court_name`、`cause` 等元数据），支持 `.to_document()` 转为 LangChain Document。
  - **环境配置**：`.env` 文件管理 `DELILEGAL_APP_ID`、`DELILEGAL_SECRET` 等。
- **系统架构**：
  - 前端（Streamlit / Gradio 输入界面）
  - 后端（FastAPI / LangChain 链式调用 deli_api → GPT 提取 → 输出生成）
  - 存储：本地缓存检索结果（可选 Redis）
- **提示工程重点**：
  - 通用模板字段映射（图片中勾选项）。
  - 动态字段生成（根据案由自动增减列）。
  - 三类裁判结论识别 Prompt（权利/金额/行为）。
- **可扩展性**：支持多案由模板（相邻关系、合同纠纷、侵权等）；未来可直接嵌入更大法律智能体。
